# nix-green

`~/nix-green` is a Nix flake that writes this user's config. Changes belong in its
Nix modules, followed by a rebuild.

## Where to edit

Resolve the file first: `readlink -f ~/.config/waybar/config`.

- `/nix/store/...` - generated by Home Manager. Edit the module that writes it
  (`grep -rln waybar ~/nix-green --include='*.nix'`) and rebuild. Never edit the
  store path or replace the link with a real file; the next rebuild fails on it or
  discards it.
- Inside `~/nix-green` - an out-of-store link (`global-agents.md`, this skill).
  Edit in place; no rebuild.
- A real file - not managed, unless it is one of these, which are writable on purpose:
  - `~/.config/hypr/hyprmoncfg-monitors.lua`, `~/.config/hyprmoncfg/profiles/` - monitor layouts (see Pitfalls)
  - `~/.config/hypr/local.lua` - per-machine Hyprland overrides, loaded last
  - VSCodium `settings.json` - keys declared in `modules/packages.nix` win on every rebuild

**`~/nix-green/dotfiles/` is not the source.** It is a hand-updated snapshot of
the generated config, kept for reference and for people who want to copy the
files without Nix. Nothing reads it. Don't edit it to change a setting, and don't
update it unless asked.

## Which setup this is

| Check | Setup | Entry module | `install.sh` target | Eval with |
|---|---|---|---|---|
| `[ -e /etc/NIXOS ]` | NixOS | `kde/home.nix`, `hyprland/home.nix` | `kde`, `hyprland` | see Apply |
| `uname -s` = `Darwin` | nix-darwin | `nix-darwin/home.nix` | (none) | `.#darwinConfigurations.nix-darwin.system.drvPath` |
| otherwise | Home Manager on a distro (Fedora) | `linux/home.nix`, `linux/hyprland.nix` | `cli`, `hyprland` | `'.#homeConfigurations."green-hyprland".activationPackage.drvPath'` (or `.green`) |

On a distro, the target is `hyprland` when `~/.config/hypr/hyprland.lua` is a store link.
`flake.nix` is the source of truth.

## Where settings live

All under `modules/` unless a path says otherwise.

| Setting | Module |
|---|---|
| Hyprland keybinds, window rules, gaps, animations, autostart | `hyprland.nix` (inline Lua) |
| Launcher, keybind cheat sheet (SUPER+K) | `rofi.nix` - keep the cheat sheet in sync with binds |
| Status bar | `waybar.nix`; macOS `sketchybar.nix` |
| Notifications, OSD, lock, idle, screensaver | `mako.nix`, `swayosd.nix`, `hyprlock.nix`, `hypridle.nix`, `screensaver.nix` |
| Colors | `palette.nix`, used by each program's module; `themes.nix`, `kdethemes.nix` for the rest |
| Wallpaper | `wallpaper` arg in `hyprland/home.nix`, `linux/hyprland.nix` |
| Which app fills a role (terminal, file manager, ...) | `apps.nix`; Fedora overrides in `linux/system-apps.nix` |
| Packages, CLI tools, VSCodium, opencode, agent files | `packages.nix` |
| herdr (agent multiplexer) keybinds, theme, UI | `herdr.nix` |
| Terminal / shell and aliases / prompt / editor | `terminal.nix` / `shells.nix` / `starship.nix` / `neovim.nix` |
| macOS window manager, launcher, system defaults, casks | `aerospace.nix`, `raycast.nix`, `nix-darwin/configuration.nix` |
| NixOS system (boot, services, users) | `configuration.nix`, `{kde,hyprland}/configuration.nix` |

## Apply

1. `git -C ~/nix-green add` any new file; flakes ignore untracked files.
2. From `~/nix-green`, `nix eval --raw` the drvPath for this setup (table above). Also run the darwin one if you changed a shared module. Off NixOS, `nixosConfigurations.*` always fails on the missing `/etc/nixos/hardware-configuration.nix`; that is the host, not a bug. To check that half, evaluate `kde/home.nix` or `hyprland/home.nix` with `home-manager.lib.homeManagerConfiguration`, setting `config.allowUnfree = true` on pkgs.
3. Switch with `~/nix-green/scripts/install.sh <target>`. The `rebuild` alias runs the same thing but only exists in interactive shells. A distro needs no root, so run it yourself. NixOS and macOS need `sudo`, so ask the user to run `! rebuild`.
4. Reload: `hyprctl reload`, `systemctl --user restart waybar` (likewise `swayosd`, `hypridle`, `swaybg`), `makoctl reload`; on macOS `sketchybar --reload`, `aerospace reload-config`.
5. Check the setting actually took effect (`hyprctl` queries, a `grim` screenshot). A clean switch is not proof.

## Pitfalls

- **Shared modules must stay cross-platform.** `nix-darwin/home.nix` imports `packages.nix`, `terminal.nix`, `themes.nix`, `apps.nix` and more. Guard Linux-only parts with `lib.mkIf pkgs.stdenv.hostPlatform.isLinux` or `lib.optionals`. A Linux-only option such as `programs.zen-browser` must not appear there at all, because `mkIf` does not suppress "option does not exist".
- **Authentication breaks with nixpkgs builds on a distro.** They expect setuid wrappers in `/run/wrappers/bin`, which only NixOS creates, so hyprlock and polkit agents fail or segfault. Use the distro's binary, branching on `hyprland != null`. See `programs.hyprlock.package = null` in `linux/hyprland.nix` and the polkit agent in `modules/hyprland.nix`.
- **Monitors belong to hyprmoncfg.** `hyprmoncfgd` applies profiles on hotplug and lid events. `hyprland.nix` loads the generated file through `guarded_dofile`, which drops disable rules that would leave no display on. Keep the include's last line shaped `do local path = ...hyprmoncfg-monitors.lua...; guarded_dofile(path) end`, because `hyprmoncfg doctor` checks it. From an agent shell, use `hyprmoncfg apply --confirm-timeout 0`. On the T480, panel + HDMI + ultrawide exceeds the display buffer, so the docked profile keeps eDP-1 off.
- **Never start `Hyprland` from an agent shell** without `WAYLAND_DISPLAY`; it grabs the real display. To debug a frozen login, set `debug.disable_logs = false`, switch to a TTY, and use `hyprctl -i 0 ...`.
- **Fedora already ships some apps.** Roles in `linux/system-apps.nix` point at them, so check for a role before adding a package.
- Match the surrounding formatting and comment style. Don't run a formatter over a whole file; the modules aren't uniformly formatted, and the diff would bury the change.
